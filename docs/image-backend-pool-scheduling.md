# 统一媒体号池调度

本文定义图片与视频请求获得后端成员时的统一运行时契约。数据库 schema、调度仓储与
系统设置实现必须保持一致。

## 成员与能力

一个分组可以包含任意数量的 `api` 成员。每个成员通过 API 上游配置声明端点、模型和
运行参数，统一参与顶层排序。

每个成员必须显式声明非空 `supportedModelIds`。请求模型只作为能力键与该集合精确匹配，
调度器不得根据前缀、模型家族或成员类型预先缩小候选集合。协议适配器可以在成员获租后
解析模型 ID，以构造对应上游载荷。

## 候选过滤

所有策略共享同一资格阶段，并按以下顺序拒绝不合格成员：

1. 成员不在请求指定分组，或分组不允许当前 Principal。
2. 成员未启用、处于终态错误、冷却中或健康状态不允许调用。
3. 成员未声明请求模型，或类型专属配置无法执行该媒体协议。
4. 当前有效租约达到成员并发上限。
5. 本轮请求已因可切换失败排除该成员。

图片和视频都没有会话粘性。资格过滤完成后才应用全局策略；任何策略都不能绕过容量、
权限、健康或模型能力条件。

## 全局动态策略

系统设置 `IMAGE_BACKEND_SCHEDULING_STRATEGY` 可在运行时选择：

- `priority`：优先级数值越小越先选择；相同优先级依次比较健康度、最久未获租、
  最久未使用和稳定成员 ID。
- `least_acquired`：累计成功获租次数最少者优先；平局依次比较优先级、健康度、
  最久未获租和稳定成员 ID。租约一旦成功即计数，与上游最终结果无关。
- `least_load`：比较 `有效在飞租约数 / 并发上限`；平局依次比较优先级、健康度、
  累计获租次数、最久未获租和稳定成员 ID。

设置缺失、非法或读取暂时失败时安全回退 `priority`。已获得的租约不因策略变更迁移，
保存后的新请求读取数据库中的新策略。

## 原子获租与释放

调度仓储在同一个 PostgreSQL 事务内锁定稳定排序的候选、清理过期租约、聚合有效在飞数、
应用策略、插入租约，并更新 `leaseAcquiredCount` 与 `lastAcquiredAt`。上游网络请求、
对象存储和其他外部 I/O 必须在事务提交后执行。

调用完成或明确失败后释放租约。进程异常时由过期时间允许其他副本回收，不能使用进程内
计数替代数据库租约事实。

## 失败切换

请求局部维护已失败成员集合。明确的提交前可切换失败会释放租约并在同一分组、同一模型和
同一策略下重选；终态用户错误、审核拒绝和无候选不切换，也不得跨分组调用。

视频取得上游任务标识或轮询地址后，后续轮询只能恢复原成员及任务持久化的请求/鉴权
Profile；Token 过期时只刷新同一 Profile，不得重新提交或切换成员。提交结果不确定时
保留诊断状态，既不换成员重投，也不自动退款。

## 可观测性

调度指标记录策略、结果、成员类型快照、成员 ID、分组、候选数和容量信息。结果至少区分
`acquired`、`switched`、`no_candidate`、`capacity_rejected` 与
`terminal_failure`。指标不得包含业务载荷、用户媒体或任何凭据。
