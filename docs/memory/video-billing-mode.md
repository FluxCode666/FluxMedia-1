# 视频双模式计费

## 计费来源与优先级

- 全局模型配置以真实模型 ID 决定 `per_second` 或 `per_item`；默认是按秒。
- 每个模型和支持分辨率都维护按秒与按条两套价格。按条的初始化默认是 3 积分，切换模式
  不得清空另一套价格。
- 分组可按同一模型和分辨率覆盖两套金额，但不能覆盖模式。可信供应商账号所属分组优先于
  用户分组，再回退全局；供应商账号本身不得保存计费配置。

## 不可变任务与财务

- 新视频任务在创建事务中把可信分组、模式、单位、单价、总价和摘要写入版本化 metadata。
  任务创建后的价格或模式变化不得影响任务、重试、恢复、API Key 配额、扣费或退款。
- `credits_transaction` 仍是唯一财务真相。按条只改变金额计算，消费和退款继续使用既有
  幂等键与双重记账不变量。
- 无新快照的升级前任务仅走 legacy 按秒路径。对外可说明其模式和实际消费，但创建单价与
  原报价必须返回未知，不得回算为当前按秒价或默认 3 积分。

## 公开接口与展示

- `video.listCapabilities` 的每个模型加分辨率报价行使用 `current_quote`，包含模式、单位、
  单价和与 Principal 绑定的短期 `quoteToken`，但不暴露分组、成员、凭据、容量、来源、摘要
  或配置 revision。
- `video.generate` 可选接收报价 token。token 只校验相同 Principal、模型和分辨率，且不得
  进入请求幂等指纹；既有任务先按原快照重放。报价陈旧时返回最新 `currentQuote`，调用方确认
  后重试。
- 新任务、查询、回调和历史都使用 `snapshot` billing DTO，包含原报价与实际消费；退款后
  保留原报价并把实际消费投影为 0。模型目录只显示当前有效模式的价格，登录用户可见可信
  分组价格，匿名用户只见全局价格。
